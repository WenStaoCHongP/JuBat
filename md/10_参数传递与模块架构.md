# 参数传递与模块架构

本文档描述电化学-热-CZM 耦合系统中的参数传递关系和整体模块架构。

---

## 1. 系统架构概览

### 1.1 模块关系

```
┌──────────────────────────────────────────────────────────────────┐
│                        JuBat 主模块                              │
│                                                                  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐│
│  │   SetCase   │  │   Solve     │  │  PostProcess│  │  CycleSolver ││
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘│

│  ┌─────────────────────────────────────────────────────────┐ │

│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐     │ │
│  │  │    SPMe    │  │  Thermal2D  │  │     CZM    │     │ │

│  └─────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

### 1.2 数据流向

```
电化学模型 (SPMe)
    │
    │ 传递内热源 q_e
    ▼
热模型 (Thermal2D)
    │
    │ 传递单元平均温度 T_e
    ▼
电化学模型 (SPMe)

电化学模型 + 热模型
    │
    │ 传递扩散应力 + 热应力
    ▼
CZM 模型
    │
    │ 传递损伤状态 D
    ▼
分流求解器 (影响电流分布)
界面热阻模型 (影响层间导热)
```

## 2. 核心数据结构

### 2.1 Case 结构体

Case 是核心配置对象，包含所有模型参数和选项：

| 字段 | 类型 | 说明 |
|------|------|------|
| `param` | Params | 无量纲化参数 |
| `param_dim` | Params | 有量纲参数 |
| `opt` | Option | 选项配置 |
| `mesh` | Dict{String, Mesh} | 网格字典 |
| `index` | Dict{String, Union{Array{Int64}, Int64}} | 状态向量索引映射 |
| `layout` | Union{Nothing, MultiSPMeLayout} | 多 SPMe 布局（类型安全） |
| `geometry` | Union{Nothing, MeshGeometry} | 几何拓扑（层权重、边界等） |
| `czm_mesh` | Union{Nothing, CohesiveMesh} | CZM 网格 |
| `czm_cache` | Union{Nothing, CZMAssemblyCache} | CZM 装配缓存（E/ν 变化时重建） |
| `czm_layout` | Union{Nothing, CzmLayout} | CZM 布局 + u_prev（跨时间步位移） |
| `czm_param_cache` | Union{Nothing, CzmParamCache} | 按-接口 CZM 参数缓存（内容哈希失效） |

> **设计约束**: `layout`、`geometry`、`czm_mesh` 使用 `Union{Nothing, T}` 类型，替代了原来的 `Dict{String,Any}`。采用 Fail-Fast 原则：直接字段访问，未初始化时 Julia 自动抛异常，不使用 `haskey`/`try-catch` 吞错误。

### 2.3 PhaseResult 结构体

存储单个阶段（充电/静置/放电）的结果：

```julia
mutable struct PhaseResult
    phase_type::PhaseType               # 阶段类型
    t_start::Float64                    # 起始时间 (s)
    t_end::Float64                      # 结束时间 (s)
    duration::Float64                   # 实际持续时间 (s)
    
    # 电化学
    V_start::Float64                    # 起始电压 (V)
    V_end::Float64                      # 结束电压 (V)
    capacity::Float64                   # 容量 (Ah)
    terminated_by::Symbol               # 截止原因 :time 或 :voltage
    
    # 热
    T_max::Float64                      # 最高温度 (K)
    T_mean_end::Float64                 # 结束时平均温度 (K)
    
    # 损伤
    D_max::Float64                      # 最大损伤
    D_mean::Float64                     # 平均损伤
    ΔD_max::Float64                     # 损伤增量
    
    # 最终状态
    final_state::Union{Dict, Nothing}

    # Raw solve result (for CSV export, only when save_detailed=true)
    solve_result::Any   # Dict from Solve(), or nothing
end
```

## 3. 关键耦合接口

### 3.1 CallModel_MultiSPMe

**功能**：多 SPMe 并行求解主函数

**函数签名**：
```julia
function CallModel_MultiSPMe(case::Case, yt::Array{Float64}, t::Float64; jacobi::String)
```

**位置**：`src/CallModel.jl`（从 `Solve.jl` 拆分而来）

**流程**：
1. 解析状态向量（提取 T_nodes 和 yt_chem，通过 `case.layout` 字段）
2. 读取缓存单元面积和计算均温
3. 计算代表性电化学变量（用于预因子）
4. 分流求解（获取 I_e）
5. 并行求解各单元 SPMe（`Threads.@threads`）
6. 计算逐单元分层热源
7. 热装配与边界条件
8. 全局拼装

**关键实现细节**（`src/CallModel.jl:22-205`）：
```julia
# 代表性状态计算（用于预因子）
yt_representative = mean(yt_chem)
T_rep = mean(Te_prev)
vars_rep = SPMe_variables(case, yt_representative, t; I_app=I_total, T_e=T_rep)

# CZM 失效单元处理：由 CZM 网格现场派生（不读取 variables 字典）
if case.opt.czm_enabled && case.czm_mesh !== nothing
    fractured_czm = get_fractured_elements(case.czm_mesh)
    deactivated_elements = Int64[]           # 经 geometry.czm_element_map 映射到热单元
end

# 渐进式面积损失（可选）：D 映射到热单元

    map_czm_damage_to_thermal(case.czm_mesh, ne) : nothing

# 分流求解（初值参数传 nothing；D_elem 启用分级面积损失）
variables, I_e, Vc = solve_branch_currents(
    case, variables, yt_representative, t,
    I_total, areas, Te_prev, nothing;
    deactivated_elements=deactivated_elements, D_elem=D_elem_area_loss
)
```

### 3.5 粘性正则化参数

**功能**：平滑 CZM 损伤演化，防止损伤跳变导致的数值不稳定

**Option 字段**：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `czm_viscous_enabled` | Bool | false | 启用粘性正则化 |
| `czm_visc_tau` | Float64 | 0.0 | 粘性松弛时间 τ_v [s] |

**离散格式**（`CouplingState.jl` 中实现）：

$$D_v^{n+1} = D_v^n + \beta \cdot (D_{eq} - D_v^n)$$

其中 $\beta = \Delta s / (\tau_v^* + \Delta s)$，$\tau_v^* = \tau_v / t_0$。

详见 `md/14_粘性正则化.md`。

### 3.4 update_czm_damage!

**功能**：更新 CZM 损伤状态

**定义位置**：`src/CouplingState.jl:535`，签名为 3 参形式
`update_czm_damage!(case, variables, T_nodes_carry)`（旧 6 参重载已随重构删除）

**调用位置**：Solve 主时间循环内每 N 个时间步调用一次
（由 `opt.czm_update_interval` 控制，默认 1 = 每步，`src/Solve.jl:267-296`）；
`solve_phase` 不再自行调用

**流程**：
1. `compute_czm_strain_inputs`（`:419`）由温度场/SOC 构造热-化学应变输入
2. `compute_czm_params_per_interface` + `ensure_czm_cache` 构建/复用参数与装配缓存
3. 调用 `solve_czm_step` 做一次 CZM 求解
4. 更新损伤变量并经 `czm_output_to_variables` 回写
5. 记录断裂单元

## 4. 参数传递流程

### 4.1 电化学 → 热

```julia
# 计算逐单元热源
for e in 1:ne
    Q_rxn_NE = as_n * abs(j_n_e) * abs(eta_n_e[e])
    Q_rev_NE = as_n * j_n_e * T_e * dUdT_n_e[e]
    Q_ohm_s_NE = I_e_local^2 / (3.0 * sig_n_eff)
    Q_ohm_e_NE = I_e_local^2 / (3.0 * kappa_ne)
    # ... 其他层类似
    q_elem[e] = 按层权重聚合
end

# 传递给热装配
variables["heat_source_fields"] = q_total * scale.L^3 / cell.volume
```

### 4.2 热 → 电化学

```julia
# 从热场提取单元均温
Te_prev = zeros(Float64, ne)
for e in 1:ne
    nds = mesh_th.element[e, :]
    Te_prev[e] = sum(T_nodes[nds]) / length(nds)
end

# 传递给 SPMe_element
SPMe_element(case, yt_chem[e], t, e; I_e=I_e[e], T_e=Te_prev[e])
```

### 4.3 CZM → 分流求解

```julia
# 获取断裂单元列表（由 CZM 网格现场派生，非 variables 键）
deactivated_elements = Int64[]
if case.opt.czm_enabled && case.czm_mesh !== nothing
    fractured_czm = get_fractured_elements(case.czm_mesh)
    for e in 1:ne, czm_idx in get(case.geometry.czm_element_map, e, Int64[])
        czm_idx in fractured_czm && (push!(deactivated_elements, e); break)
    end
end

# 渐进式面积损失（可选）：D 超阈值单元按 (1-D)/(1-D_threshold) 缩减有效面积
D_elem = case.opt.czm_area_loss_enabled ? map_czm_damage_to_thermal(case.czm_mesh, ne) : nothing

# 传递给分流求解器
solve_branch_currents(...; deactivated_elements=deactivated_elements, D_elem=D_elem)
```

### 4.4 CZM → 热模型

当前有两条作用路径：

1. **断裂单元热源屏蔽**（默认路径）：`compute_heat_sources_with_czm`（`src/ThermalDistributed.jl:390`）
   将完全断裂单元的热源置零；
2. **界面热阻导热衰减**（**已禁用**，v2 修订 2026-07-21）：损伤影响界面导热系数并装配到
   热刚度矩阵的代码块整体注释禁用（`src/ThermalDistributed.jl:166-190`），见 md/07。
   恢复后装配形式为：

```julia
# h_eff 由按-接口参数计算（CzmInterfaceParams，非 Cohesive）
h_eff = compute_gap_conductance(D, δ_n, param_cache.by_interface[:PE_PCC])

# 装配到热刚度矩阵
coeff = h_eff * czm_elem.length
K[nb,nb] -= coeff
K[nb,nt] += coeff
```

## 5. 类型安全布局结构体

> **历史**: 原始实现使用 `case.multi_spme_layout::Dict{String,Any}` 和 `case.thermal_extras::Dict{String,Any}` 传递布局和几何信息。结构体重构后迁移为类型安全的 struct 字段（`case.layout`、`case.geometry`），消除了 `haskey`/`try-catch` 等反模式。

### 5.1 MultiSPMeLayout

**定义**：`src/CouplingState.jl`

```julia
struct MultiSPMeLayout
    ne::Int                        # 热单元数
    n_chem::Int                    # 每单元电化学 DOF 数
    nT::Int                        # 热节点 DOF 数
    n_total::Int                   # 全局状态向量总长 = ne*n_chem + nT
    chem_range::UnitRange{Int}     # 1:(ne*n_chem)
    thermal_range::UnitRange{Int}  # (ne*n_chem+1):(ne*n_chem+nT)
    areas::Vector{Float64}         # 预计算的单元面积（网格不变量）
end
```

**构造器**：

| 构造器 | 说明 |
|--------|------|
| `MultiSPMeLayout(ne, n_chem, nT)` | 3 参数便捷构造器，areas=zeros(ne) |
| `MultiSPMeLayout(ne, n_chem, nT, mesh_th)` | 4 参数构造器，从 mesh 计算面积 |

**使用示例**：
```julia
layout = case.layout
ne = layout.ne
offset = (e - 1) * layout.n_chem
areas = layout.areas           # 缓存的单元面积
```

## 6. 求解器分支说明

### 6.1 热模型专用分支 (`Solve.jl`)

当 `opt.model == "thermal"` 时，求解器会进入热模型专用分支（`src/Solve.jl:2-75`），
该分支有特殊的时间处理方式与入参约定：

```julia
# src/Solve.jl:1-8（节选）
function Solve(case; ...,
    thermal_variables=nothing,        # model=="thermal" 时必填，缺失即报错
    thermal_update_fn=nothing,        # 热源更新函数（可选）
    thermal_record=false, ...)        # 是否记录 T_hist 全历史

    if case.opt.model == "thermal"
        thermal_variables === nothing &&
            error("Solve: model==\"thermal\" requires thermal_variables keyword argument")
        t0 = case.opt.time[1]/case.param.scale.t0      # 无量纲初始时间
        t_end = case.opt.time[end]/case.param.scale.t0  # 无量纲终止时间
        dt = case.opt.dt[1]/case.param.scale.t0        # 无量纲时间步长
        # ... 后续求解使用无量纲时间
    end
```

**关键特性**：

1. **自动时间归一化**：
   - 输入的物理时间自动除以 `param.scale.t0` 转换为无量纲时间
   - 求解器内部所有时间变量均为无量纲

2. **热源更新函数接口**：
   - `thermal_update_fn` 作为 `Solve` 的 kwarg 注入，接收无量纲时间参数
   - 验证脚本需要先将物理时间转换为无量纲时间
   - `thermal_variables` 字典必须包含 `"thermal2D temperature at nodes"`（无量纲初温）

3. **结果时间转换**：
   - 纯热分支返回命名元组 `(time, T_nodes, T_hist)`，`time` 与温度均为无量纲量
   - 需要分别乘以 `scale.t0` / `scale.T_ref` 还原为物理量

**验证脚本使用示例**：

```julia
# 设置热模型选项
opt.model = "thermal"
opt.time = [0.0, 60.0]  # 物理时间 [s]
opt.dt = [0.2, 2.0]      # 物理时间步 [s]

# 热源更新函数（接收无量纲时间）
t_vec_nd = collect(t_phys) ./ param.scale.t0  # 预先转换为无量纲
function update_heat_source(t_nd, vars)
    q_at_t = interpolate(t_vec_nd, q_ring_nd, [t_nd])
    vars["heat_source_fields"] = q_at_t
end

# 求解（thermal_variables 必填）
ring_sol = JuBat.Solve(case;
    thermal_variables = variables,
    thermal_update_fn  = update_heat_source)

# 结果转换回物理时间/温度
t_phys = ring_sol.time     .* param.scale.t0
T_K    = ring_sol.T_nodes  .* param.scale.T_ref
```

**与其他分支的区别**：

| 特性 | `model == "thermal"` | `model == "SPMe"` |
|------|---------------------|-------------------|
| 时间尺度 | 内部归一化为无量纲 | 内部归一化为无量纲 |
| 热源更新 | 使用无量纲时间 | 使用无量纲时间 |
| 结果时间 | 需要转换回物理时间 | 需要转换回物理时间 |
| 主要用途 | 纯热模型验证 | 电化学-热耦合 |
