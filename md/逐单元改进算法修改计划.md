在保持现有代码风格前提下、改动面可控且可回退的修改计划。

## 变更目标与约束

- 目标
  - 基于当前热场 T_e 和初始 I_seed，为每个热单元构建对应的 SPMe “电化学状态概要”（至少含 η_n/η_p、dUdT_n/dUdT_p、 U_n/U_p 等），生成逐单元内热源。
  - 热传导更新温度后，调用分流求解得到新的 I_e，作为下一时间步初值。
- 约束
  - 保持 variables 字典风格和键命名习惯（"thermal2D ..." 前缀）。
  - 不打破现有 Solve 时间推进和装配风格（blockdiag 拼接、t0 与 t_th 缩放一致）。
  - 可一键回退到当前流程（留开关，不影响现有用户）。

## 代码改动总览

- 新增：逐单元“批处理”求变量
  - 文件：`src/SPMe.jl`
  - 新增函数：`SPMe_variables_batch(case, yt, t; I_e::Vector{Float64}, T_e::Vector{Float64})::NamedTuple`
- 调整：热源公式支持逐单元键（优先使用）
  - 文件：ThermalDistributed.jl
  - 函数：`heatQ_Source`
- 调整：主求解里完成“逐单元构建 → 热源 → 热装配 → 分流”的顺序与初值管理
  - 文件：`src/Solve.jl`
  - 函数：`Solve` 主循环 和 `CallModel`
  - 新开关：`case.opt.thermal_assembly_site::String = "Solve" | "CallModel"`（默认 "CallModel"，以保持兼容）

下面给出逐文件的具体修改计划。

---

## 1) SPMe.jl：新增批处理函数

新增函数签名与约定：
- 输入
  - case, yt, t：与 `SPMe_variables` 一致
  - I_e::Vector{Float64}：逐单元无量纲分电流（初值或上一步结果）
  - T_e::Vector{Float64}：逐单元温度（无量纲 T*）
- 输出（NamedTuple）
  - eta_n_e::Vector{Float64}, eta_p_e::Vector{Float64}
  - dUdT_n_e::Vector{Float64}, dUdT_p_e::Vector{Float64}
  - U_n_e, U_p_e（用于诊断/更精细热源）
  - kappa_ne_e/kappa_pe_e/kappa_sp_e 或 R_EL_e（若要把欧姆项也完全 per-element）
- 计算说明（保持风格）
  - 参考 `SPMe_variables` 中的公式，把和 T/I 有关的部分向量化；prefactor（由 cn_surf、cp_surf、ce_*_gs 与几何积分得到）使用当前 yt 和 mesh 一次性计算，并在元素上复制/聚合。
  - 过电位：
    - j_n(e) = I_e[e] / (a_n * L_n)，j_p(e) = -I_e[e] / (a_p * L_p)
    - j0_n, j0_p 用 Arrhenius(T_e[e]) 与 prefactor 计算
    - eta_n_e[e] = 2 T_e[e] asinh(j_n/2/j0_n)，eta_p 类似
  - dUdT：
    - 可先用 `param.NE.dUdT(cn_surf)`/`param.PE.dUdT(cp_surf)` 的代表值（标量）填充成向量；后续易升级为逐单元。
  - 输出结果仅写回到返回的 NamedTuple，不直接污染 variables（由 Solve 再写入）。

命名与风格：
- 保持函数内局部显式变量、适度使用 @inbounds，避免隐式全局。
- 不更改现有 `SPMe_variables` 行为。

## 2) ThermalDistributed.jl：热源优先使用逐单元键

函数：`heatQ_Source`
- 读取键优先级（有则用；无则回退到旧逻辑）
  - 优先：`"thermal2D eta_p_e"`, `"thermal2D eta_n_e"`, `"thermal2D dUdT_p_e"`, `"thermal2D dUdT_n_e"`, `"thermal2D element current"`
  - 回退：当前实现的全局 `I_app` 与 `[1]/[end]` 截断方式
- 新的反应/可逆热公式（逐元素）：
  - Q_rxn[e] = abs(I_e[e] * (eta_p_e[e] - eta_n_e[e]))
  - Q_rev[e] = abs(I_e[e]) * T_e[e] * (dUdT_p_e[e] - dUdT_n_e[e])
- 欧姆热：沿用现有实现（已依赖 I_e² 和温度依赖电导率，空间是本地化的）；若后续要完全 per-element，可通过 `SPMe_variables_batch` 返回 R_EL_e 等来替代。
- 单位与缩放：保留 `opt.units_thermal` 分支输出 SI 或无量纲 q*。
- 回退行为：若缺少逐单元键，打印一次 @warn 并使用旧路径，确保鲁棒。

保持风格：
- 继续用 variables 字典与已有键名风格。
- 保持装配与缩放位置不变。

---

## 3) Solve.jl：把“逐单元构建与热装配”放到主循环

新增配置开关：
- 在 Option 中新增 `thermal_assembly_site::String`（默认 "CallModel"）。
- 在 `CallModel` 里，当 `distributed2D` 且 site=="Solve" 时，跳过热装配（只返回电化学 M/K/F 与 variables）。

Solve 主循环修改（关键步骤）：
1. 在 while 循环开始时，维持均温写回（现有简耦合）不动。
2. 调用 `CallModel` 获取电化学 M/K/F 与 variables（此时不含热学 block）。
3. 若 `opt.thermal_enabled && thermalmodel=="distributed2D" && thermal_assembly_site=="Solve"`：
   - 确保 `variables["T_nodes"]` 存在（若无则填初温）。
   - 计算元素面积 `areas`（可复用已有缓存键 `"thermal2D element area"`）。
   - 计算元素均温 `T_e`。
   - 构造 I_e 初值：
     - 若已有 `I_e_prev`（本地变量或 `variables["thermal2D element current"]`），则用它；
     - 否则 `I_seed = (areas/sum(areas)) * I_total`（I_total 读取 `variables["cell current"]`，为无量纲）。
   - 批处理电化学变量：
     - `batch = SPMe_variables_batch(case, yt, t; I_e=I_seed, T_e=T_e)`
     - 把 batch 中的 eta/dUdT/U 向量写入 variables：
       - `"thermal2D eta_p_e"`, `"thermal2D eta_n_e"`, `"thermal2D dUdT_p_e"`, `"thermal2D dUdT_n_e"`（以及可选 U 向量）
   - 分流求解（使用上步 I_e 作为初值）：
     - `variables, I_e, Vc = solve_branch_currents_newton(case, variables, yt, t, I_total, areas, T_e, I_e_prev)`
     - `I_e_prev = I_e`（保存到局部，必要时也写回 variables）
   - 计算热源：
     - `variables = heatQ_Source(case, variables, t, yt)`（此时将优先使用逐单元键）
   - 热学装配与边界条件：
     - `MT, KT, FT = ThermalDistributed2D(case, variables)`
     - 时间尺度匹配：`MT .*= (t0/t_th)`（与现有 CallModel 一致）
     - `ThermalDistributed2D_BC(KT, FT, case, t)`
   - 与电化学拼装：
     - `M = blockdiag(Me, sparse(MT))`
     - `K = blockdiag(Ke, sparse(KT))`
     - `F = [Fe; FT]`
4. 继续现有时间推进：解 y_c，回写热自由度到 `variables["T_nodes"]`，记录历史等。
5. 循环末尾，保留越界电压中断逻辑。

风格要点：
- 直接借用现有 CallModel 分支中的“面积/均温/缩放/BC 拼装”代码片段，避免重写新风格。
- 局部变量清晰命名，尽量少分支嵌套；保持 @inbounds 在热点循环处。

## 变量与接口“契约”

- 新增 variables 键（写入 Solve 主循环）：
  - `"thermal2D eta_p_e"`, `"thermal2D eta_n_e"`::Vector{Float64}
  - `"thermal2D dUdT_p_e"`, `"thermal2D dUdT_n_e"`::Vector{Float64}
  - 可选 `"thermal2D U_p_e"`, `"thermal2D U_n_e"`::Vector{Float64}
- 读取优先级（`heatQ_Source`）：
  - 若上述键存在则使用逐单元公式；否则回退旧路径。
- 分流初值：
  - 优先用 `I_e_prev`（Solve 局部），否则用面积加权 I_seed。
  - 也可同步写回 `variables["thermal2D element current"]` 以便调试与外部访问。

## 回退与兼容

- 默认不开启：`opt.thermal_assembly_site = "CallModel"` 行为保持现状不变。
- 开启“方案 B”：仅当 `opt.thermal_assembly_site = "Solve"` 时，`CallModel` 跳过热装配，Solve 接管。
- 缺键回退：`heatQ_Source` 缺逐单元键时打印一次警告并使用旧公式，避免中断。

## 验收与测试建议

- 正确性
  - 验证 `sum(w .* I_e) ≈ I_total`；
  - 打印 `q_elem` 的 min/mean/max 与空间图像，观察与 T_e 分布的相关性。
- 能量守恒
  - 在每步热解后调用 `energy_balance_log!`，看 residual（无量纲）是否稳定小于 1e-2 ~ 1e-3。
- 稳定性
  - 零电流工况：`I_total=0` 时 I_e=0，反应/可逆热≈0。
  - 电压越界：保持现有钳位/抛错行为。
- 性能
  - 记录单步耗时；与“方案 A”相比开销增长比。
  - 如有需要，可把 batch 中与网格无关的 prefactor 缓存到 case.param（只要 yt 不变）。

---

## 风险与缓解

- 计算量增加：用向量化/一次积分（prefactor）；必要时增加开关只导出 eta/dUdT，暂不回填更多局部量。
- 公式重复：将 `SPMe_variables` 与 batch 中共用的片段提炼成小工具函数，或注释标明来源，降低漂移风险。
- 双路径维护：用 `thermal_assembly_site` 单点切换，尽量不要复制粘贴大片逻辑（热装配/BC 直接复用现有实现）。
