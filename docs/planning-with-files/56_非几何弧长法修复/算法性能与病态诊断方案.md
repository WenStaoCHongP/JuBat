# 非几何弧长法性能与病态诊断实施计划

> **执行说明**：按本文件逐项实施并在每项后核对证据；本文件是方案，创建时尚未执行下面的代码改动。使用 `executing-plans` 的检查点流程。诊断先于优化；不得把运行时间长直接归因于矩阵病态或无限循环。

> **2026-09-25 进度**：构造受损步已证实终点重复缩步（259 次校正），而从同一已接受状态的严格定载校正 3 次可收敛。现对一次到达目标的失败弧长子步先做一次定载校正，并设 `max(2·max_iter,8·n_load_steps)` 的暂定单物理步校正预算；这不是旧五循环冻结失败步的经验阈值。该步尚未冻结，下面的病态判定与 A/B 项仍未完成，预算需据真实轨迹复核。

**目标：** 区分非几何 CZM 弧长路径的矩阵病态、非线性路径停滞和重复计算，再以最小改动消除已证实的算法开销与无进展长跑。

**架构：** 在已有 `solve_czm_arc_length_step` 与恢复的五循环算例上采集同一物理步的计数、时间、线性残差和弧长/损伤状态。冻结该步后做同输入 A/B；数值判据不因提速而放宽，外部 `MechState` 只在目标载荷严格平衡后提交。

**技术栈：** Julia 1.11.2、SparseArrays/UMFPACK、JuBat 非几何单元平均 CZM；Windows PowerShell。

**依据：** [当前代码审查](findings.md)、[首轮长算例日志](../../../output/testexample_soc065_5cycles/arc_fix_20260924/console.log)、[第二轮中止日志](../../../output/testexample_soc065_5cycles/arc_fix_final_20260924/console.log)。外部实现见文末链接。

## 已确认事实与待判问题

| 事项 | 当前证据 | 判定 |
|---|---|---|
| 首圈放电完成但耗时不可接受 | 第二轮在同参下完成 1800 s 放电（3.771→3.236 V、2.500 Ah）；约一小时后仍在首圈静置，按用户要求人工停止，进程累计 CPU 3524 s | 真实性能问题；静置是否越过旧 43 s 失败点未知 |
| 是否代码级无限循环 | `max_substep_attempts=max(100,20*n_load_steps)`；本配置为 200，每次最多 `max_iter=100` 校正 | 单次机械调用有界，但理论上可达约 2 万次校正；相位反复调用足以形成实际无进展长跑 |
| 重复稀疏分解 | 诊断前的预测及校正分别直接调用 `K_bc \ F_load_bc`、`K_bc \ R_bc`、`K_bc \ F_load_bc`；同一次校正对同一矩阵求两次解。`basic` 已用 `solve_czm_linear_system_cached!` | 明确实现上的重复工作；nθ=80 未损伤矩阵的两个右端小试验约 0.299 s→0.155 s，整场占比仍未知 |
| 矩阵是否病态 | 现有长算例没有保存 `K_bc`、线性求解误差或因子状态 | 未判；不可从耗时或 `D≈1` 单独推断 |
| 候选损伤是否污染残差 | 原非几何弧长在损伤试算未通过平衡门后，仍把试算历史赋给下一 Newton 候选；nθ=8 同位移对照，先试算高张开再回到低张开使内力相差 95.4% | 已确认算法实现错误；不能据此断言它是原 43 s 失败步的唯一原因 |
| 损伤耦合切线是否一致 | 对构造的 D_max=0.967202 状态，复合残差 `R(u,D_trial(u))` 沿同一位移方向有限差分，在扰动 `1e-4` 至 `1e-8` 下与 `K_total·u` 相差约 22.5353% | 确认此状态下缺少单元平均试算损伤对位移的链式导数；原失败步的幅度待测 |
| 弧长路径是否停滞 | 日志曾见 `λ=0.9992459946803237` 缩步，`residual=6.53e-10`；该值混合不同尺度且缺少 `|g|/s²` | 未判；要分别记录力残差、相对约束误差与根方向 |

## 全局约束

- 第一阶段只诊断，不改容差、荷载、涂层或界面参数，不打开粘性、几何非线性或塑性。
- 不以密集 `cond(K)` 计算替代诊断：矩阵维度大，改用线性后向误差、因子状态与可用的条件数粗估。Julia 1.11.2 当前 `SparseArrays.UMFPACK` 未提供 `rcond`，不得把其他版本文档中的接口当作本地可用。
- 每次记录同时写物理时间、循环/相位、`λ`、接受/失败子步数、牛顿次数、两根与上一接受切向夹角、`‖R‖`、`|g|/s²`、试算损伤前后残差，以及装配/分解/回代耗时。诊断输出仅存 `output/testexample_soc065_5cycles/`，临时探针不留在生产源码。
- 所有 A/B 使用同一冻结输入与线程设置；逐位或按已声明浮点误差比较位移、D、历史最大分离、残差、接受路径及失败回滚。不能用“运行更快”替代科学结果验收。
- `geo_nonlinear=true` 球面弧长、`basic`、`gp_basic` 不在本方案的数值改动范围；60 s `example/testexample.jl` 强制基线保持记录精度一致。

## Task 1：冻结单步并判定病态或路径问题

**文件：** 临时诊断仅改已恢复的 `example/testexample_soc065_5cycles.jl` 和必要的 `src/CzmSolve.jl` 诊断点；结果写 `output/testexample_soc065_5cycles/arc_diagnosis/`。最终撤销探针，不新增研究脚本。

- [ ] 在现有五循环算例中开启受控诊断，只对目标 CZM 物理步保存入口 `u`、损伤历史、`F_ext`、热/化学增量、BC 与选项；写入时带循环、相位、物理时间。冻结输入须可在同一现有算例入口重放，禁止保存只含输出的后态。
- [ ] 在预测、每次校正与损伤试算后记录上表量；把现有混合 `residual` 拆成 `force_residual` 与 `arc_error_rel`。记录两根判别分数和所选根，避免凭 warning 推断折返。
- [ ] 同一 `K_bc`、同一右端计算 `η=‖K_bc x-b‖/(‖K_bc‖·‖x‖+‖b‖)`；记录因子化成败、非有限值、对角尺度跨度和本地实际可用的条件估计。小的后向误差仅证明求解残差小，**不能排除病态矩阵**；若弧长约束/损伤提交失败，另查非线性算法。若 `η` 大或分解失败，再查矩阵缩放、零刚度与约束。
- [ ] 用冻结步分别运行原版与只记录诊断的版本，核对输出完全一致；将计数与耗时写入 `arc_diagnosis.md`，确认重复分解、装配、回代及终点 `basic` 的占比。停止条件是拿到可复现输入与明确分类，不继续盲跑五圈。
- [ ] 对冻结失败步补做 `R(u,D_trial(u))` 的有限差分切线检查。若误差与小网格一样在缩小扰动后不消失，推导并装配 `D_trial` 的跨积分点链式导数，或以明确标识的非精确 Newton 法加全残差线搜索；任何方案都要用冻结步证明平衡与路径收敛。

## 外部源码对照

- [PETSc `SNESNEWTONAL` 源码](https://petsc.org/main/src/snes/impls/al/al.c.html)：每次 Jacobian 设置一次 `KSP` 算子，同一上下文依次求载荷方向与残差方向；区分最大 Newton 次数、最大 continuation 增量，失败给明确原因。其 `normal correction` 更省计算但文档注明可能影响收敛，不能直接替换本项目精确根。
- [OpenSees `ArcLength.cpp`](https://github.com/OpenSees/OpenSees/blob/master/SRC/analysis/integrator/ArcLength.cpp)：通过同一个 `LinearSOE` 求方向并求二次根，虚根与零分母明确返回错误。此处说明复用线性系统对象的架构；不把其球面 `alpha²` 公式误套到本项目柱面约束。
- [Julia `factorize` 文档](https://docs.julialang.org/en/v1/stdlib/LinearAlgebra/#LinearAlgebra.factorize)：因子对象可反复求多个右端；本项目已有按矩阵内容精确比较的缓存函数。
- [SparseArrays `UMFPACK.rcond` 说明](https://sparsearrays.juliasparse.org/dev/solvers/#SparseArrays.UMFPACK.rcond)：是缩放后因子对角的粗估，不是 `1/cond₂(K)` 的界。
