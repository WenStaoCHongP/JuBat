# Findings & Decisions

## Requirements
- Review `docs/superpowers/specs/2026-08-04-src-simplification-design.md`.
- Review every implementation plan associated with that spec.
- Judge them against `Simplify/reducing-ai-code-bloat-plan.md`.
- Provide evidence-based, prioritized feedback; do not implement source changes.
- Run `example/testexample.jl` before simplification and freeze its output as the behavioral baseline.
- Require later simplification runs to match the frozen baseline.

## Review Criteria
- Baseline alignment: preserve behavior, consolidate duplication, remove compatibility debris, avoid speculative abstractions.
- Scope completeness: every baseline recommendation is accepted, rejected with rationale, or deferred explicitly.
- Plan atomicity: concrete file/function targets, bounded steps, no vague bulk rewrites.
- Dependency correctness: safe order, migration/compatibility boundaries, integration sequencing.
- Verification: characterization tests before risky edits, exact commands, measurable acceptance gates.
- Net simplification: deletion/consolidation targets and no replacement with equivalent scaffolding.
- Documentation consistency: names, paths, terminology, ownership, and completion conditions agree.
