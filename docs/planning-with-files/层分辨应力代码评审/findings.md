## 最终评审问题

1. **应力历史存在伪零列。** `StandardVariables` 为全部输出步预分配零矩阵，但 `Solve` 仅在 `czm_step_count % czm_update_interval == 0` 时写第 `v` 列；`PostProcessing` 又把 `1:v` 全部作为有意义历史导出。若最终步不落在更新间隔，`couple_example.jl` 直接取 `[:, end]`，会把未计算的零列画成最终应力云图。新增测试第 81 行反而把首列保持零作为预期，没有覆盖间隔大于 1 的集成路径。实际 `nθ=8`、固定 0.5 s 步长、`czm_update_interval=2` 探针得到 5 列应力历史，其中倒数第二列最大绝对值为 0，而末列为 100943.44 Pa，证实伪零列存在。
2. **仍生成用户明确要求删除的散点径向剖面。** `example/couple_example.jl` 第 326--341 行创建并保存 `final_hoop_stress_radial_profile.png`，实施基线也把它列入四张 PNG；这与“仅做最终温度、环向应力、切向应力三张云图；不要散点图”冲突。
3. **已知非零材料热膨胀系数被写成零。** Jellyroll 参数把 SP、Al 集流体和 Cu 集流体 `alphaT` 显式设为 0，同时注释给出非零物理范围；新的逐层本征应变会直接消费这些零，从而在标称“热 + 扩散”应力中静默删除三类层的热应变。这违反项目“缺失工程状态不得伪装为零”的契约，应补可靠参数或让热应力能力显式不可用。
4. **应力列的时间标签错位。** `Variable_update!` 在 `Solve.jl:235` 先把 `variables["time"] == t` 写入第 `v` 列，随后 `t += dt`，CZM 快照使用推进后的 `t`，最后 `export_macro_stress(..., v, ...)` 把该次 CZM 解写回旧时间标签的第 `v` 列。最终云图标题来自 `result["time [s]"][end]`，但应力对应下一 CZM 时刻；同时温度取新 `y_c`、SOC 仍来自此前 `CallModel`，负载还混合了两个时间层。
