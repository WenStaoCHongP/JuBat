## 关键问题

1. `thermal_to_czm_interp` 为什么以 2524/3366 为列数，而活动热状态只有 1322/1763 个节点？
2. 插值矩阵构造时传入的“热节点”是否实际来自 CZM 加密子网格？
3. 缓存是否在热网格或 CZM 网格变化后没有失效？
4. 最小修复应落在哪个文件，是否需要跨文件调整？

## 决策

| 决策 | 理由 |
|---|---|
| 先诊断后修改 | 用户要求分析原因，且既有逐文件审批流程仍有效 |
| 以端到端对象尺寸为证据 | 单元测试均通过，问题仅在真实网格组合中出现 |
| 绑定活动热网格而非硬编码 merged | 理论要求插值矩阵定义域与实际求解温度场一致；merged 只是当前配置 |
| 同入口严格校验矩阵、父单元和 SOC | 三者共同构成理论式 (3.95a)–(3.95c) 的完整输入契约 |
