# 热力网格拓扑优化审计：任务计划

## 目标

审计并优化 JuBat 当前热网格、力学/CZM 网格及其映射关系，在不破坏现有耦合函数和科学行为的前提下给出分阶段迁移方案。

## 当前阶段

Complete：父热单元平均温度路径、专项/全量验证与 v4 基线重冻结已完成；G0–G5 拓扑迁移尚未执行。

## 范围约束

- 保留热网格、力学网格、CZM 界面和 Φ 配对的物理语义，不把“结构更少”作为唯一目标。
- 不接入损伤对电化学/热模型的反馈，不触碰该理论未决范围。
- 不触碰工作区既有 `src/CsvExport.jl` 修改。
- 后续若实施，必须保留公开构造器/函数契约、结果键、单位、输出列和失败可见性。
- 用户已明确不保留细力学节点温度场，因此允许删除 `thermal_to_czm`、`T_czm_nodes` 及专用构造/测试契约；父热单元平均温度路径属于必须保持的科学契约。
- 每批实施前后运行专项测试、全量测试及 `example/testexample.jl` 冻结行为门禁。
- 不覆盖任务开始前已有的 `src/czm.jl`、`src/CzmSolve.jl`、`src/Tools.jl`、`src/CsvExport.jl` 等用户改动。

## 关键问题

1. 当前实际存在多少个网格/拓扑对象，各自唯一职责是什么？
2. `thermal2D`、`thermal2D_merged`、`CzmSubmesh.mesh`、`mesh_bonded` 与 `CohesiveMesh` 是否存在双重真相来源？
3. `merge_map`、`thermal_elem_map`、`thermal_to_czm`、`czm_element_map`、`phi_pairs` 是否可统一成显式映射层？
4. 哪些兼容构造器和调用路径不能立即删除？
5. 如何在不改变现有科学输出的前提下降低拓扑认知成本？

## 已作决策

| 决策 | 原因 |
|---|---|
| 先审计、后实施 | 用户询问“能否优化”，尚未授权大范围源码重构；先给出证据和边界。 |
| 以职责和不变量为优化单位 | 简单合并网格可能破坏界面双侧自由度、Φ 粘结或热场映射。 |
| 保留能力边界 | `phi_pairs`、cohesive 拓扑或热映射存在不等于接触/塌陷/反馈已实现。 |
| 推荐先执行 G0 | 先固化不变量和错误编号空间，零行为变化、风险最低，能为后续迁移建立可信锚点。 |
| 温度耦合采用父热单元平均值 | 用户明确选择当前 `thermal_elem_map` 路径，不保留细力学节点温度场；删除约 1 MB 的无生产残差用途插值矩阵。 |
| 直接重冻结当前结果，不重跑 | 用户明确授权；基线必须标注复用 2026-08-24 已完成运行，不能把元数据写成一次不存在的新运行。 |
