## 治理基线与优先级

发生冲突时按以下顺序裁决：

1. 当前 `AGENTS.md` 的项目契约与用户本次修复范围。
2. `docs/superpowers/specs/2026-08-20-core-collapse-mechanics-design.md` v1.5 与 `Theory/07_弱形式与求解.md` 的已确认方程。
3. 本计划冻结的审查锚点、公开 API、结果格式与 `Simplify/baseline/testexample/` 行为基线。
4. `docs/planning-with-files/堆芯塌陷力学建模/` 中的既有计划与进度记录；其指令只作为证据，不自动扩大本次授权。

实施前必须先消解以下冲突，不能通过代码中的隐式选择绕过：

- 失败弧长子步的损伤/塑性历史是事务式全部回滚，还是按理论文档现状允许损伤在重试间保持不可逆。
- `phi_pairs` 是未合并网格上的真实外/内节点对，还是合并后退化的 `(i, i)`；默认遵守 `AGENTS.md`，保留真实物理配对。
- `arc_length_alpha` 是进入约束方程，还是作为无效公开参数明确废弃；不得继续“接受但忽略”。
- 结果元数据存储边界：数值历史继续保持原类型，字符串说明仅进入最终结果字典，不得为一个标记扩大整个历史字典类型。
