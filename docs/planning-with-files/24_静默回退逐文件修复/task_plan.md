# 静默回退逐文件修复计划

## 目标

按照用户逐文件批准、逐文件修改、逐文件审阅的流程，消除会掩盖工程问题并造成科学结果失真的回退逻辑。

## 当前状态

恢复执行中：`src/Solve.jl` 与经用户授权联动的 `src/CouplingState.jl` 已通过后续审阅；CZM—热插值尺寸和热力网格拓扑问题已在独立批次修复。正在依据当前源码校准剩余队列。

## 强制工作流

1. 一次只处理一个 `src/` 文件。
2. 修改前报告该文件的具体问题、拟改范围和验证方法。
3. 得到用户明确批准后才能修改。
4. 修改并验证完成后立即停止，交给用户审阅。
5. 用户审阅通过后才报告下一个文件的问题。
6. 仅在用户明确授权时，允许为完整修复一个接口问题而将直接依赖文件纳入同一原子批次。

## 决策

| 决策 | 理由 |
|---|---|
| `cool_method` 未知值和 `tab` 无极耳不进入修复队列 | 用户确认操作人员只设置合法值，且无极耳是 `tab -> none` 的模型极限 |
| 先处理 `CyclePostProcess.jl` | 它包含当前必现的结果键错配，修复范围局部且便于单独审阅 |
| `Solve.jl` 批次联动修改 `CouplingState.jl` | 用户明确允许跨文件调整；只有返回完整 `CZMResult` 才能输出真实快照诊断 |
| `ThermalDistributed.jl` 不增加电导率有限/正值判断 | 用户确认这是材料数值定义及操作人员输入责任，不做防呆设计 |
| 将当前 `testexample` 行为重建为正式基线 | 用户确认 CycleSolver 批次并授权修改基线；重建后再进入下一文件只读报告 |
