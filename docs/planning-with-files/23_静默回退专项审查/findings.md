# 静默回退专项审查发现

## 用户要求

- 检查代码中与 `u_czm_prev` 回退相似的情况。
- 核心风险：工程状态有问题时不应静默用零值或默认值继续计算，以免结果失真。
- 当前任务仅审查和报告，不主动批量修改源码。

## 审查范围

- 主范围：`src/**/*.jl`。
- 重点模式：`zeros`/`zero` 回退、`get(..., default)`、三元默认值、`try/catch` 吞错、`NaN`/`Inf` 替换、尺寸不符重置、缺失字段自动补值。

## 优先级结论

### P0：当前结果已确定失真

1. `CyclePostProcess.jl:52,61` 使用不存在的热结果键，`T_mean_end` 必然回退为初始温度。
2. `Solve.jl:283-307` 的 CZM 快照把牵引力、迭代次数和残差写成固定零值，CSV 诊断不是实际求解结果。

### P1：工程错误会被掩盖并继续求解

1. `Solve.jl:95-105,122-125` 和 `CycleData.jl:53-61`：缺失/错误外部状态重新初始化。
2. `Solve.jl:273-312`、`CouplingState.jl:527-599`：CZM 异常、非有限输入或不收敛后继续推进时间。
3. `Parallelsolution.jl:361-432`：面积退化或 Newton 不收敛后仍使用当前分流电流。
4. `Mechanical.jl:294-322`：力学求解失败用零位移，退化单元用零应力。
5. `CouplingState.jl:443-474,728-735`：缺失 SOC、非法单元映射或插值失败被零值/最近节点替代。
6. `ThermalDistributed.jl:283-284`：非法电导率被提升为微小正值；冷却方式仅按操作人员设置合法值的前提审查，不将未知字符串分支列为缺陷。
7. `Variables.jl:258-273`、`Solve.jl:217-224`：变量尺寸错误留下零历史或沿用旧温度。
8. `Tools.jl:38,90-92`、`Czm.jl:153-181`、`Jellyrollmodel.jl:281-282,682-683`：退化网格被跳过、置零、夹边界或赋极小量。
9. `SetParams.jl:258-268`、`CycleData.jl:85`、`Solve.jl:32-52`：未知电芯/离散格式/热模型被解释成另一种有效配置。
10. `CycleSolver.jl:159-165`、`CyclePostProcess.jl:45-86`：缺失阶段结果被包装成完整时长、初始温度、零松弛等有效指标。

### P2：导出结果看似有效但数据缺失

1. `CsvExport.jl:215-219` 把 `NaN` 写成 `0.0`。
2. `CsvExport.jl:289,392-400,529-546` 对尺寸不足补零或少写单元。
3. 多处导出循环对缺失阶段、时间、热场或映射直接 `continue`，文件仍显示写入成功。

## 建议修复原则

- 必需状态、物理参数、网格不变量和求解收敛采用 `error`/`ArgumentError`/`@assert`，不要自动重建或补零。
- 可选输入只在函数契约明确声明时允许默认值；缺失科学输出使用 `missing`/`NaN`，不能写成物理零。
- 在 `SetCase` 或独立 `validate_case!` 集中验证模型名、求解格式、冷却方式、正值参数、网格映射和状态尺寸。
- 求解器返回统一状态对象并由调用方强制检查 `converged`；CZM/分流失败不得静默推进时间。
- 统一结果键名和单位，通过常量或访问函数读取，避免字符串漂移。

## 研究发现

- 非有限值相关候选集中在 `CouplingState.jl`、`CzmSolve.jl`、`Parallelsolution.jl`、`CsvExport.jl`。
- 必需状态使用默认值的首批高价值候选：
  - `CouplingState.jl:449-450`：缺失单元 SOC 时用全零向量。
  - `Solve.jl:176`：缺失热节点温度时用空向量。
  - `CycleSolver.jl:160,164`：缺失求解结果字段时用空历史或空字典。
  - `CyclePostProcess.jl:45-63`：多个求解结果字段用空数组、零矩阵或空字典。
- `CsvExport.jl` 有大量输出层默认值；需区分“仅让导出缺失值可见”与“把 `NaN` 改成 0.0 导致报表失真”。
- `CzmSolve.jl` 的 `try/catch` 多处可能属于线性求解失败后的受控不收敛路径，尚不能直接判为静默回退。
- `Solve.jl`、`Mechanical.jl`、`CycleSolver.jl`、`CsvExport.jl` 存在异常捕获，需逐段检查是否重新抛出或显式终止。
- 已确认的高风险候选：
  - `Solve.jl:95-105`：调用方传入状态字典但缺少 `"y"` 时，静默重新初始化模型；循环连续性会被破坏。
  - `Solve.jl:122-125`：外部状态长度不匹配时仅警告并重新初始化；上一阶段状态丢失但求解继续。
  - `Solve.jl:273-312`：CZM 更新的任意异常只写 `@debug`，主求解继续；默认日志级别下异常不可见，损伤更新被跳过。
  - `CouplingState.jl:449-450`：CZM 必需的单元 SOC 缺失时伪造全零 SOC 输入。
  - `CouplingState.jl:443-446,463-474`：非法 `thermal_elem_map` 索引被跳过，预分配零值被当作合法温差/SOC 增量。
- `CouplingState.jl:527-533` 对 CZM 输入 `NaN` 只警告后继续求解；与 `Solve.jl` 吞掉后续异常组合后，可能让仿真静默跳过损伤演化。
- `CouplingState.jl:586-599` 对 CZM 不收敛仅警告、不提交损伤但仍返回并让时间推进；是否允许这种“保持旧损伤继续”需按项目失败策略确认，暂列高风险候选。
- 第二轮显式回退检索新增候选：
  - `CzmBC.jl:11-12`：刚度矩阵为空或全零时条件数尺度回退旧值。
  - `Czm.jl:51-54`：厚度或热膨胀字段缺失时存在保持旧行为的默认值。
  - `SetParams.jl:339`：cohesive 数据缺失时把 `scale.δ_czm` 回退为 `scale.L`。
  - `CouplingState.jl:645`：插值失败时回退最近粗热节点。
  - `CzmSolve.jl:488`：缺少初始位移 `u0` 时使用零向量；更可能是公共求解器的合法初猜，需要看调用契约。
- 导出层存在明确的数据美化行为：`CsvExport.jl:215-219` 把 `NaN` 换成 `0.0`，`289,395-398` 在数组长度不足时输出物理零值；这些不会改变求解，但会使导出结果看起来有效，属于结果失真风险。
- `CyclePostProcess.jl` 的零值分母保护多数是指标未定义时输出 0，可能误导后处理但不影响主求解，需单独按“报告失真”分级。
- 归一化/力学上下文判读：
  - `Czm.jl:57-64` 在 `scale.σ_czm <= 0` 时将跨尺度转换因子设为 `1.0`。生产 CZM 路径会先经过 `compute_czm_params_per_interface` 的 `scale.σ_czm > 0` 断言，因此当前属于被上游挡住的遗留回退；仍建议删除以免直接调用绕过契约，但不列当前高风险结果失真。
  - `SetParams.jl:333-346` 对缺失 cohesive 锚点仅警告，并令 `δ_czm=L`、`σ_czm=0`、`G_czm=0`、`K_czm=0`；这使一个不完整参数对象继续进入归一化。若 CZM 未启用则可能是兼容需求，若启用则必须在入口硬失败。
  - `CzmBC.jl:12-13` 对空/全零刚度矩阵使用固定罚值 `1e12`；这会把结构刚度缺失伪装为可施加边界条件的系统。高风险，应至少对启用 CZM 的求解路径报错。
  - `CouplingState.jl:728-735` 在找不到包含 CZM 节点的热单元时，用最近热节点插值且无诊断；网格错位会被悄悄转化为看似合理的温度。高风险。
  - `Czm.jl:469-480` 对零长度 cohesive 单元赋任意单位方向继续构造几何；即使后续长度因子可能令贡献为零，也掩盖退化网格。高风险。
- `CzmSolve.jl:488` 的 `u0=nothing -> zeros` 是函数签名明确允许的初始猜测，当前主调用已传入 `u_prev`，暂不列为缺陷。
- `Czm.jl:623` 的 `F_ext=nothing -> zeros` 表达“无外部机械载荷”，在热化学载荷仍显式传入的情况下属于合理可选输入，暂不列为缺陷。
- 宏观力学中确认两处高风险静默失真：
  - `Mechanical.jl:294-299` 捕获任意线性求解异常后用全零位移继续恢复应力场；输出不再代表平衡解。
  - `Mechanical.jl:322` 对退化 Q4 单元（中心梯度不可算）直接跳过，该单元应力保留为零且没有诊断。
- `Mechanical.jl:272-273` 与 `CzmBC.jl` 相同：全零刚度时改用固定罚值继续，应纳入同一修复项。
- `CallModel.jl:8-18` 的损伤映射对越界 `cohesive_to_thermal` 索引直接忽略，相关热单元得到零损伤；这是拓扑错误被解释为“无损伤”。中高风险。
- `CallModel.jl:85` 的 `get(czm_element_map, e, [])` 本身不一定错误，因为并非每个热单元都必须覆盖 CZM；需要用映射完整性约束整体检查，不能逐键强制存在。
- `Tools.jl:38` 的通用 Q4 积分器遇到近零 Jacobian 时直接跳过该高斯点，未报告退化/翻转单元；任何调用方都会少算积分贡献。高风险。
- `ThermalDistributed.jl:60-65` 在未提供边界缓存时现场计算缓存，是合理的惰性构造，不属于掩盖错误。
- `CycleSolver.jl:159-165` 在求解结果缺少时间历史时把阶段时长设成 `t_max`，缺少 `final_state` 时创建空字典并写入全局时间；这会把不完整求解结果包装成“阶段完整运行”。高风险。
- `CsvExport.jl:81-90` 捕获单个文件写入异常、警告并记录到 `files_skipped`，属于显式的批量导出容错，不改变科学结果，暂不列为缺陷。
- 循环后处理进一步确认：
  - `CyclePostProcess.jl:45-64` 对缺失时间、电压、温度及最终状态分别伪造计划时长、初始电压、初始温度和空状态，随后仍计算容量与阶段结果。高风险，且与 `CycleSolver.jl:159-165` 重复兜底。
  - `CyclePostProcess.jl:15-17,78-86` 在静置阶段任一浓度状态缺失时返回零方差并输出零松弛率，缺失数据被表示为有效的“无松弛”。中风险。
  - `CyclePostProcess.jl:74` 对未知或缺失终止原因统一解释为 `:time`，可能掩盖异常终止。中风险。
  - `CyclePostProcess.jl:107-108` 充电容量为零时库仑效率输出 `0.0` 而不是未定义值/错误，属于报告层语义失真。中低风险。
- `CycleData.jl:53-61` 也会在传入状态缺少 `"y"` 时重新初始化；需确认该入口是否仍被生产调用，若是则与 `Solve.jl` 同级高风险。

  - `Variables.jl:258-264` 当变量向量行数与历史矩阵不一致时不写入也不报错，预分配零值留在该时间步；后处理会把维度错误看成真实零值。

- `Solve.jl:428-433` 的 `final_state["T_nodes"]` 也可作为规范末态来源，但它是归一化温度，使用时必须乘 `T_ref`；建议统一通过一个状态访问函数避免再次出现键名/单位错配。
- 测试覆盖检索未发现 `T_mean_end`、错误热键、分流不收敛、CZM 更新异常或宏观力学零位移回退的负向测试。`smoke_thermal_bc.jl` 只遍历三个合法冷却方法，没有验证未知方法或极耳节点为空必须失败。
- 多个示例仍读取旧键 `"thermal2D T_nodes [K]"`/`"thermal2D T_nodes history [K]"`；这些直接索引会报错而非静默失真，但说明热结果键已发生漂移，进一步支持集中定义键名。
- `Option.jl`/`SetCase.jl` 没有发现统一的枚举值或物理参数验证入口；当前依赖各函数自行分派，导致同一无效选项在不同路径中有时报错、有时回退。
- 分流求解器确认一个高风险失败传播问题：
  - `Parallelsolution.jl:246-293` 在奇异 Jacobian、线搜索失败或达到迭代上限后返回 `converged=false` 和当前迭代值。
  - `Parallelsolution.jl:409-432` 随后仍重新缩放这些电流并写入物理变量；调用方 `CallModel_MultiSPMe` 不检查 `"thermal2D Vsolve converged"`，继续用不满足公共电压平衡的电流推进 SPMe/热模型。高风险。
  - `Parallelsolution.jl:361-371` 未检查有效面积总和；全部有效面积为零时 `w=A_eff/sum(A_eff)` 产生非有限权重，最终也可能走上述“未收敛但继续”路径。高风险。
  - `Parallelsolution.jl:378-381` 对越界失效单元索引直接忽略，CZM 拓扑/映射错误可能少停用单元。中风险。
- `line_search` 的 `return 0.0, V` 本身是内部失败信号；问题不在这个回退值，而在上层仅记录标志却照常使用未收敛解。
- 热边界和参数选择判读：
  - `ThermalDistributed.jl:121-123` 选择 `cool_method="tab"` 但没有极耳节点时退化为无冷却系统；这是极耳冷却的极限情况，按项目模型定义等价于 `none`，不属于缺陷。`144-146` 的零总弧长沿用同一语义。
  - 按用户给定前提，操作人员只会设置受支持的 `cool_method`，因此未知字符串最终原样返回 `K,F` 的分支不纳入本次缺陷清单。
  - `SetParams.jl:258-268` 的 `ChooseCell` 对未知 `CellType` 没有 `else/error`，将继续使用结构默认参数。高风险。
- `SetParams.jl:273-290` 在单体密度/比热为零时按各层加权推导，是明确的参数派生规则；只要分母和分层参数另有正值约束，就不是与本次相同的静默回退。
- `SetMesh.jl:342-344` 虽然先跳过退化边，但未裁剪的 `ele=0` 会在随后 `ShapeFunction2D` 索引时报 `BoundsError`，因此不会静默产出结果；错误位置不友好，但不属于本次“继续计算导致失真”。`745-747` 同理由上游映射决定，暂不列确定缺陷。

## 技术决定

| 决定 | 理由 |
|---|---|
| 先宽检索再逐处判读 | 单纯搜索会把正常初始化和数值算法保护混入候选，必须结合语义去误报 |
| 不把所有默认值视为错误 | 配置默认值、可选输出和求解器初猜通常是合法设计 |
| 本轮不批量修改源码 | 用户要求是检查；先给出证据与修复顺序，避免一次性改变失败策略和基线行为 |
| 假设操作人员只设置合法 `cool_method` | 因此不审查未知冷却字符串；`tab` 模式无极耳按模型定义等价于 `none` |
