# 内存溢出问题修复说明

## 问题描述

运行`testexample.jl`时出现内存溢出错误：

```
ERROR: OutOfMemoryError()
Stacktrace:
  [6] zeros
    @ .\array.jl:589 [inlined]
  [7] StandardVariables(case::Main.JuBat.Case, num::Int64)
    @ Main.JuBat D:\OneDrive\Desktop\JuBat\JuBat\src\Variables.jl:107
```

## 问题根源

### 1. 时间步数计算问题

在`src/Solve.jl`第76行：
```julia
num = round(Int64, (t_end - t0)/dt * 1.5)
```

问题：
- 如果`dt_min`很小，`num`会非常大
- 例如：dt=1e-5秒，t_end=3600秒 → num ≈ 5.4亿步
- 预分配1.5倍缓冲进一步放大了问题

### 2. 多SPMe模式的内存需求

对于多SPMe模式（`per_element_spme=true`），每个时间步需要存储：
- `ne`个单元（例如12,608）
- 多个变量（电流、过电位、温度等）
- 每个变量：`Float64` (8字节)

**内存需求计算**：
```
单个变量 = ne × num × 8 bytes
         = 12,608 × 540,000 × 8
         = 54 GB！
```

对于6个变量 = 324 GB内存！这显然超出了普通计算机的容量。

## 修复方案

### 修复1：限制最大预分配步数 (`src/Solve.jl`)

```julia
# 计算预期时间步数，添加安全限制
num_estimated = round(Int64, (t_end - t0)/dt * 1.5)

# 限制最大预分配步数
max_steps = 100000  # 默认
if hasproperty(case.opt, :per_element_spme) && case.opt.per_element_spme
    max_steps = 50000  # 多SPMe模式限制更严格
end
num = min(num_estimated, max_steps)

if num_estimated > max_steps
    @warn "预期时间步数超过限制，将使用动态扩展"
end
```

**效果**：
- 最大预分配：50,000步（多SPMe）或100,000步（普通）
- 单个变量内存：12,608 × 50,000 × 8 = 5 GB（可接受）
- 6个变量总计：约30 GB

### 修复2：动态扩展数组 (`src/Variables.jl`)

在`Variable_update!`函数开头添加：
```julia
# 检查是否需要扩展数组
for k in keys(variables_hist)
    if isa(variables_hist[k], Array{Float64}) && ndims(variables_hist[k]) == 2
        current_size = size(variables_hist[k], 2)
        if v > current_size
            # 扩展50%或至少1000步
            expansion_size = max(1000, current_size ÷ 2)
            @warn "时间步 $v 超过预分配 $current_size，扩展 $expansion_size 步"
            n_rows = size(variables_hist[k], 1)
            new_cols = zeros(Float64, n_rows, expansion_size)
            variables_hist[k] = hcat(variables_hist[k], new_cols)
        end
    end
end
```

**效果**：
- 如果实际步数超过预分配，自动扩展
- 避免数组越界错误
- 性能轻微下降（扩展时需要复制）

## 使用建议

### 1. 调整时间步长

如果收到内存警告，考虑增大时间步长：

```julia
opt.dt = [0.1, 10.0]  # [dt_min, dt_max] 单位：秒
```

**经验值**：
- 快速测试：dt_min = 1.0秒
- 正常仿真：dt_min = 0.1秒
- 高精度仿真：dt_min = 0.01秒（需要更多内存）

### 2. 减少仿真时间

对于初步测试：
```julia
opt.time = [0.0, 360.0]  # 仅仿真6分钟
```

### 3. 减少网格密度

减少周向单元数：
```julia
mesh_th = jellyroll_collector_seed_mesh(param_dim; nθ=40)  # 从80降至40
```

**影响**：
- 内存需求减半
- 空间分辨率降低

### 4. 关闭逐单元变量存储（如果不需要）

如果不需要每个单元的详细历史数据：
```julia
opt.per_element_spme = false  # 关闭逐单元存储
```

**效果**：
- 大幅减少内存需求（约90%）
- 仍然保留全局平均值和关键变量

## 内存需求估算

### 公式

```
总内存 ≈ ne × n_vars × num_steps × 8 bytes
```

其中：
- `ne`：单元数（例如12,608）
- `n_vars`：变量数（约6个）
- `num_steps`：时间步数
- 8：Float64字节数

### 示例

| 配置 | ne | num_steps | 内存需求 |
|------|-----|-----------|---------|
| 粗网格，短时间 | 3,152 | 10,000 | 1.5 GB |
| 中等网格，中等时间 | 12,608 | 50,000 | 30 GB |
| 细网格，长时间 | 50,432 | 100,000 | 242 GB ❌ |

### 推荐配置

**16 GB内存系统**：
- ne ≤ 12,608
- num_steps ≤ 30,000
- 或 per_element_spme = false

**32 GB内存系统**：
- ne ≤ 25,216
- num_steps ≤ 50,000

**64 GB+内存系统**：
- ne ≤ 50,432
- num_steps ≤ 100,000

## 故障排除

### 仍然内存不足？

1. **检查dt值**：
   ```julia
   println("dt_min = ", opt.dt[1], " 秒")
   println("预期步数 = ", (opt.time[2] - opt.time[1]) / opt.dt[1])
   ```

2. **增大dt_min**：
   ```julia
   opt.dt = [1.0, 10.0]  # 增大最小时间步
   ```

3. **减少网格**：
   ```julia
   mesh = jellyroll_collector_seed_mesh(param_dim; nθ=20)  # 更粗网格
   ```

4. **关闭详细记录**：
   ```julia
   opt.per_element_spme = false
   ```

### 性能下降？

如果频繁触发动态扩展：

1. **增加初始预分配**：
   编辑`src/Solve.jl`，增大`max_steps`：
   ```julia
   max_steps = 100000  # 增大限制
   ```

2. **使用固定时间步**：
   ```julia
   opt.dtType = "fixed"
   opt.dt = [0.5, 0.5]  # 固定0.5秒
   ```
