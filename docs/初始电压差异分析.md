# 初始电压差异分析

## 问题描述

**testexample.jl** (多SPMe模式) 和 **testexample_simple_coupling.jl** (简化耦合模式) 的初始电压不同：

| 模式 | 初始电压 | 差异 |
|------|---------|------|
| 多SPMe | 3.9992 V | - |
| 简化耦合 | 4.0637 V | **+0.064 V** |

## 可能的原因

### 1. **初始 SOC 不同** ⭐ (最可能)

#### 分析

Jellyroll 电池的初始浓度参数（`parameters/Jellyroll.jl`）:

```julia
# 负极
NE.cs0 = 29866 mol/m³
NE.cs_max = 33133 mol/m³
NE.theta_init = 0.901

# 正极
PE.cs0 = 17038 mol/m³  
PE.cs_max = 63104 mol/m³
PE.theta_init = 0.270
```

根据 `theta_100` 和 `theta_0` 值：
- **负极 SOC**: (0.901 - 0.0263) / (0.9106 - 0.0263) ≈ **99.0%**
- **正极 SOC**: (0.8540 - 0.270) / (0.8540 - 0.2638) ≈ **98.9%**
- **平均 SOC**: 约 **99%**

#### 电压-SOC 关系

在高 SOC 区域（95-100%），典型的 dV/dSOC ≈ 0.3-0.8 V。

如果电压差 0.064 V 由 SOC 差异引起：
```
ΔV = 0.064 V
假设 dV/dSOC ≈ 0.5 V
→ ΔSOC ≈ 0.064 / 0.5 = 12.8%
```

**结论**: 如果是 SOC 差异，两个模式的初始 SOC 差异约为 **13%**。

#### 可能原因

1. **多SPMe 的逐单元初始化**
   - `ModelInitialisation_MultiSPMe` 可能对每个单元使用略低的 SOC
   - 或者某些单元的 SOC 被调整

2. **简化耦合使用不同的初始化**
   - `ModelInitialisation_SimpleCoupling` 直接使用 `cs0`
   - 可能没有考虑某些调整因素

### 2. **初始化代码的差异**

#### 标准初始化 (Initialisation.jl)

```julia
csn0 = ones(Float64, Nrn) * case.param.NE.cs0
csp0 = ones(Float64, Nrp) * case.param.PE.cs0
```

#### 简化耦合初始化 (ModelInitialisation_SimpleCoupling.jl)

```julia
csn0 = ones(Float64, Nrn) * case.param.NE.cs0
csp0 = ones(Float64, Nrp) * case.param.PE.cs0
```

**看起来相同**，但实际使用时可能有细微差异。

### 3. **参数归一化的时机**

#### 可能的差异点

```julia
# 归一化后
param.PE.cs0 = param_dim.PE.cs0 / param_dim.PE.cs_max  # = 0.270
param.NE.cs0 = param_dim.NE.cs0 / param_dim.NE.cs_max  # = 0.901
```

如果两个模式在**不同的时机**读取或修改了 `cs0`，可能导致初始状态不同。

### 4. **电解质浓度的影响**

电解质浓度影响离子电导率，从而影响欧姆压降：

```julia
EL.ce0 = 1000 mol/m³
```

如果两个模式的电解质初始化不同，会导致：
- 不同的离子电导率
- 不同的浓度过电位
- 不同的欧姆压降

**但在初始时刻（无电流）**，这些影响应该很小。

### 5. **初始化时的瞬态过程**

某些初始化方法可能包含：
- 预充电步骤
- 平衡步骤
- 初始电流脉冲

导致初始状态实际上不是真正的"初始"状态。

## 诊断方法

### 方法 1: 输出初始状态

在两个脚本的初始化后添加：

```julia
# 在 main() 函数中，Solve() 之前
println("\n[诊断] 初始状态:")

# 提取初始颗粒浓度
y0_chem = # 根据模式提取化学部分
Nrn = case.mesh["negative particle"].nlen
Nrp = case.mesh["positive particle"].nlen

csn_init = y0_chem[1:Nrn]
csp_init = y0_chem[(Nrn+1):(Nrn+Nrp)]

# 转换为 theta
theta_n = mean(csn_init)  # 已归一化
theta_p = mean(csp_init)  # 已归一化

@printf("  负极 theta_init = %.4f\n", theta_n)
@printf("  正极 theta_init = %.4f\n", theta_p)

# 计算 OCV
U_p = case.param_dim.PE.U(theta_p * case.param_dim.PE.cs_max / case.param_dim.PE.cs_max)
U_n = case.param_dim.NE.U(theta_n * case.param_dim.NE.cs_max / case.param_dim.NE.cs_max)
OCV = U_p - U_n
@printf("  理论 OCV = %.4f V\n", OCV)
```

### 方法 2: 运行诊断脚本

```bash
julia tools/diagnose_initial_voltage.jl
```

该脚本将：
- 计算 Jellyroll 电池的初始 SOC
- 显示 OCV 曲线
- 估算 SOC 差异

### 方法 3: 比较初始化函数

直接对比：
- `src/Initialisation.jl` 中的 `ModelInitialisation`
- `src/ModelInitialisation_SimpleCoupling.jl` 中的 `ModelInitialisation_SimpleCoupling`
- `src/Initialisation.jl` 中的 `ModelInitialisation_MultiSPMe`

### 方法 4: 检查参数文件

确认 `parameters/Jellyroll.jl` 中的：
```julia

```

是否在两个测试中被修改。

## 可能的解决方案

### 方案 1: 统一初始 SOC

如果差异是无意的，应该统一初始化：

```julia
# 在两个测试脚本中显式设置相同的 SOC
param_dim = JuBat.ChooseCell("Jellyroll")

# 统一设置为 99% SOC
target_soc = 0.99
param_dim.NE.cs0 = param_dim.NE.theta_0 + target_soc * (param_dim.NE.theta_100 - param_dim.NE.theta_0)
param_dim.NE.cs0 *= param_dim.NE.cs_max

param_dim.PE.cs0 = param_dim.PE.theta_0 - target_soc * (param_dim.PE.theta_0 - param_dim.PE.theta_100)
param_dim.PE.cs0 *= param_dim.PE.cs_max
```

### 预期结果

- 初始 theta 应该相同
- 初始 OCV 应该相同
- 在 t=0 时（无电流），电压应该等于 OCV

如果发现差异，说明初始化代码存在不一致。

## 理论参考

### OCV 计算公式

```
V_cell(t=0) = U_p(θ_p) - U_n(θ_n)
```

其中：
- `U_p(θ)`: 正极开路电势（vs. Li/Li+）
- `U_n(θ)`: 负极开路电势（vs. Li/Li+）
- `θ = cs / cs_max`: 归一化浓度

### SOC 与 theta 的关系

**负极**（嵌锂石墨）:
```
θ_n = θ_n,0 + SOC × (θ_n,100 - θ_n,0)
```

**正极**（脱锂氧化物）:
```
θ_p = θ_p,0 - SOC × (θ_p,0 - θ_p,100)
```
