## 2. main 分支基准架构

main 分支的 `Solve.jl` 约 120 行，架构极其清晰：

```
Solve()                     <- 时间步进循环 (~80行)
  |
  +-- 初始化 (y0, dt, theta, 预分配)
  |
  +-- while t <= t_end      <- 核心循环
       |
       +-- CallModel()      <- 薄调度器 (~20行)
       |    +-- SPM / SPMe / P2D / sP2D   <- 物理模型,统一返回 (M,K,F,vars,y_phi)
       |    +-- ThermalLumped (可选)        <- 直接 blockdiag 拼接
       |
       +-- 时间离散: y_new = Mt \ (Kt*y_old + Ft)
       +-- ErrorEstimation  -> 自适应 dt
       +-- Variable_update! -> 记录
       +-- 电压截止检查     -> break
```

### 2.1 核心设计模式

| 模式 | 描述 |
|------|------|
| Solve 是纯时间步进器 | 只管 dt、误差估计、记录，不懂任何物理 |
| CallModel 是薄调度器 | 按模型类型分发，统一返回 (M,K,F,variables,y_phi) 五元组 |
| blockdiag 拼装 | 电化学返回 (M,K,F)，热模型也返回 (M,K,F)，直接对角拼 |
| 无耦合逻辑在 Solve 内 | 热耦合（仅 lumped）在 CallModel 里一行 blockdiag 搞定 |

### 2.2 main 分支 CallModel 完整代码 (参考)

```julia
function CallModel(case::Case, yt::Array{Float64}, t::Float64; jacobi::String)
    if case.opt.model == "SPM"
        M, K, F, variables = SPM(case, yt, t, jacobi=jacobi)
        y_phi = Float64[]
    elseif case.opt.model == "SPMe"
        M, K, F, variables = SPMe(case, yt, t, jacobi=jacobi)
        y_phi = Float64[]
    elseif case.opt.model == "P2D"
        M, K, F, variables, y_phi = P2D(case, yt, t, jacobi=jacobi)
    elseif case.opt.model == "sP2D"
        M, K, F, variables, y_phi = sP2D(case, yt, t, jacobi=jacobi)
    else
        error("Error: $(case.opt.model) model has not been implemented!")
    end
    if case.opt.thermalmodel == "lumped"
        MT, FT = ThermalLumped(case, variables)
        M = blockdiag(M, sparse(MT))
        K = blockdiag(K, sparse(zeros(1,1)))
        F = [F; FT]
    end
    return M, K, F, variables, y_phi
end
```

## 4. 目标架构设计（已被 02 文档取代）

> **注意：本节已被 `02_全局架构与约束.md` 取代。** 原方案"不新增 .jl 文件"的约束已改为"允许新增"。本节保留供历史参考，不作为实施依据。

### 4.1 设计策略

核心思路：**不增文件，只迁移和拆分函数**。

```
策略1: 函数迁移 —— 把函数从错误的文件移到正确的文件

策略3: 职责收窄 —— 每个文件只做一件事，不相关的逻辑迁出
```

### 4.4 从 Solve.jl 迁出的逻辑

| 当前位置 (Solve.jl) | 目标位置 | 行数 |
|---------------------|----------|------|
| 文件日志重定向 (1-35行) | 提取为 `setup_logging()` 辅助函数，留在 Solve.jl 顶部 | -35→+10 |

### 4.5 关键原则

1. **Solve 只管时间** -- dt自适应、误差估计、终止判断
2. **CallModel 只管当前步** -- 给定 (case, yt, t) 返回 (M,K,F,vars,y_phi)
3. **物理求解器不知道耦合** -- SPMe_element 不知道分流、热源
4. **不新增文件** -- 通过函数迁移和拆分实现解耦

### 4.6 统一命名规范

| 类别 | 规范 | 示例 |
|------|------|------|
| 公开函数 | snake_case | `solve()`, `call_model()`, `compute_heat_sources()` |
| 内部辅助函数 | snake_case | `extract_element_state()`, `debug_check_*()` |
| 变量键（内部） | 小写+下划线 | `"q_rxn_ne"`, `"element_current"` |
| 变量键（输出） | 大写+单位 | `"Q_rxn_NE [W/m3]"`, `"temperature [K]"` |
| struct 类型 | PascalCase | `MultiSPMeLayout`, `CouplingState` |
