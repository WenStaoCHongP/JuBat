## 三、发现的问题

### 🔴 问题1: 时间尺度转换公式错误

#### 错误位置
- `src/Solve.jl`, line 723 (`CallModel_MultiSPMe`)
- `src/Solve.jl`, line 869 (主求解器装配)

#### 错误描述
时间尺度转换公式使用了倒数，导致时间步长计算错误。

#### 原代码
```julia
# ❌ 错误：公式倒数了
t_ratio = case.param_dim.scale.t_th / case.param_dim.scale.t0
```

#### 修复后代码
```julia
# ✅ 正确
t_ratio = case.param_dim.scale.t0 / case.param_dim.scale.t_th
```

#### 物理推导
对于相同的物理时间步 `Δt_phys`：
```
Δt_elec* = Δt_phys / t0  (电化学无量纲时间步)
Δt_th* = Δt_phys / t_th  (热学无量纲时间步)

因此：
Δt_th* = Δt_elec* · (t0 / t_th)

公式：t_ratio = t0 / t_th  ✅
```

#### 影响分析

**典型参数**:
- `t0 = 3600 s` (电化学时间尺度)
- `t_th ≈ 1667 s` (热扩散时间尺度，果冻卷)
- 正确比值: `t0/t_th ≈ 2.16`
- 错误比值: `t_th/t0 ≈ 0.46`

**后果**:
- ❌ 热学时间步被缩小了 **4.7 倍**
- ❌ 计算效率降低
- ❌ 可能导致数值不稳定
- ❌ 耦合迭代收敛变慢

## 四、修复内容

### 修复1: `CallModel_MultiSPMe` 中的时间步转换

**文件**: `src/Solve.jl`, line 723

**修改**:
```diff
- t_ratio = case.param_dim.scale.t_th / case.param_dim.scale.t0
+ t_ratio = case.param_dim.scale.t0 / case.param_dim.scale.t_th
```

**用途**: 将电化学时间步转换为热学时间步
```julia
dt_th_nd = dt_elec_nd * t_ratio
```

### 修复2: 主求解器中的质量矩阵调整

**文件**: `src/Solve.jl`, line 869

**原代码与注释不一致**:
```julia
# 注释说：将热质量矩阵按 t_ratio = t0/t_th 放大
# 但代码是：
t_ratio = case.param_dim.scale.t_th / case.param_dim.scale.t0  # ❌ 倒数了
```

**修复**:
```diff
- t_ratio = case.param_dim.scale.t_th / case.param_dim.scale.t0
+ t_ratio = case.param_dim.scale.t0 / case.param_dim.scale.t_th
```

**物理意义**:
主求解器使用 `t0` 时间尺度，热模块使用 `t_th` 时间尺度。
为了统一，需要调整质量矩阵：
```
MT_eff = MT * (t0/t_th)
```

这样在主求解器中：
```
MT_eff · (T^{n+1} - T^n) / dt_elec = KT · T + FT
```
等价于：
```
MT · (T^{n+1} - T^n) / dt_th = KT · T + FT
```
